# Decision Record Template

의사결정 문서(ADR)는 "왜 이 결정이 필요했고, 어떤 선택지를 비교했고, 왜 이 방식을 선택했고, 무엇을 감수했는가"가 남게 작성한다.

확인되지 않은 항목은 지어내지 말고 `(작성 필요)`로 남긴다.

## 작성 순서

1. 배경과 문제를 먼저 적는다.
2. 선택지는 최소 2개 이상 비교한다.
3. 최종 결정과 결정 이유를 분리한다.
4. 트레이드오프와 후속 작업을 솔직하게 적는다.

## 상태 값

- `제안됨`: 아직 논의 중
- `결정됨`: 채택되어 적용 중
- `변경됨`: 이후 다른 결정으로 대체됨

## 템플릿

```markdown
# [의사결정] {결정 내용을 한 줄로}

- 번호: {예: 0001}
- 작성일: {YYYY-MM-DD}
- 상태: {제안됨 / 결정됨 / 변경됨}
- 관련 기능/도메인: {예: cart, order, payment}
- 관련 파일: {예: CartItem.java, OrderService.java}

## 배경 / 문제

{어떤 요구사항, 오류, 팀 컨벤션, 확장성 문제 때문에 결정이 필요했는지 작성}

## 결정 기준

이번 결정에서 중요하게 본 기준은 다음과 같다.

- {예: 팀 컨벤션 준수}
- {예: 데이터 정합성}
- {예: 테스트 용이성}
- {예: 구현 복잡도}
- {예: 동시성 안전성}

## 고려한 선택지

### 선택지 A: {이름}

- 장점:
  - {장점 1}
  - {장점 2}
- 단점:
  - {단점 1}
  - {단점 2}

### 선택지 B: {이름}

- 장점:
  - {장점 1}
  - {장점 2}
- 단점:
  - {단점 1}
  - {단점 2}

### 선택지 C: {있으면 작성}

- 장점:
  - {장점}
- 단점:
  - {단점}

## 결정

**{최종 선택한 방식}** 을 선택한다.

## 결정 이유

- {결정적인 이유 1}
- {결정적인 이유 2}
- {프로젝트 컨벤션이나 실제 코드와 연결되는 근거}

## 감수한 것 / 트레이드오프

- {이 선택으로 포기하거나 감수한 단점}
- {추후 개선이 필요한 부분}

## 결과 / 후속 작업

- {적용 결과}
- {추가 테스트나 리팩토링 필요사항}
- {팀원 공유 필요사항}

## 참고 자료

- {관련 코드, README, PR, 공식 문서, 이슈 링크 등}
```

## 8 team 프로젝트에서 자주 쓸 수 있는 ADR 주제 예시

- Cart를 첫 상품 추가 시 생성하기로 한 결정
- CartItem 삭제를 soft delete로 처리하기로 한 결정
- 주문 생성 요청을 cartItemIds 기반으로 받기로 한 결정
- OrderItem에 주문 시점 상품명/가격 스냅샷을 저장하기로 한 결정
- 일반 주문 재고 차감을 조건부 UPDATE로 처리하기로 한 결정
- PortOne 외부 호출과 DB 트랜잭션을 분리하기로 한 결정
